## Claude によるアップデート（2026-09-25）

2026-09-24 に中断していたフロントエンドのCD（S3・CloudFrontへの自動デプロイ）が、アクセスキー方式への切り替えで完了した。

### 実施した内容

1. **IAMユーザー `github-actions-deploy` を作成**
   S3（`rebuild-frontend-first`）とCloudFront（該当ディストリビューション）だけに絞ったインラインポリシー `rebuild-frontend-deploy-policy` を付与。アクセスキーはGitHubのSecrets（`AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`）に登録。

2. **`.github/workflows/frontend-deploy.yml` の認証ステップを差し替え**（ユーザーが実施）
   OIDCのロール引き受けから、Secretsのアクセスキーを使う方式に変更。不要になった `permissions: id-token: write` も削除。
   → `Deploy Frontend` ワークフローが成功することを確認。

### 残っている課題

- OIDC認証の失敗原因は未特定のまま。IAM ID プロバイダー `token.actions.githubusercontent.com` とIAMロール `github-actions-rebuild-frontend` は再挑戦用に残している（現在は未使用）
- main へのpushで `RebuildReact/` 配下が変更された場合のみ、`Frontend CI` と `Deploy Frontend` でlint/testが二重実行される（`Deploy Frontend` は `paths` 条件があるため、それ以外の変更では動かない）。1つのワークフローに統合し、`needs` で依存させる予定
- バックエンド（EC2）のデプロイは未自動化（Dockerイメージのビルド → レジストリへ保存 → EC2で取得・再起動、の仕組みが必要）
- アクセスキーは長期有効な認証情報なので、定期的なローテーションが必要
