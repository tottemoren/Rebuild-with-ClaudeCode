## Claude によるアップデート（2026-10-14）

リポジトリから最終ゴールが読み取れるかを確認したところ、「何を作るか」は設計書にある一方、「どこまでできたら完成か」「どの順番で進めるか」がどこにも無かった。利用者と最終ゴールと優先順位を決め、ロードマップ `docs/00-roadmap.md` を新しく作った（`feature/roadmap`）。ドキュメントだけの変更で、本番への影響はない。

### 実施した内容

1. **`docs/00-roadmap.md` を新規作成**
   - 最終ゴール：個人開発で広告収入を得られるレベルのWebアプリとして公開し、運用・保守しながら利用者の反応を見て改善を続けられる状態にする
   - 優先順位：①公開 ②学習 ③ループ（AIが実装し機械が検証する流れは、①②を進める手段として整える）
   - 期間：2026年10月から半年〜1年。2027年4月に、正式リリースできたか・期限を延ばすかを判断する
   - 5つの段階（安全に公開できる状態／v1の機能を揃える／運用の土台／正式リリース／運用・改善）と、各段階の完了条件・現在地（完了・一部済み・未着手）
   - 本番構成：ECS を目標としつつ、常時かかる費用が今の EC2 より大きいため、移行の時期は段階3の終わりに、費用・必要性・学習の観点で判断する
   - 広告審査は、ログインが必要なアプリだと通りにくいことがあるため、条件の調査を段階2に前倒しで入れた

2. **`CLAUDE.md` の「開発予定・今後の目標」に1行追加**
   作業を提案する前に `docs/00-roadmap.md` で現在の段階と次の項目を確認し、そこから次の一手を提案する、とした。

3. **`docs/Study/07-working-with-ai.md` に「AIにゴールの地図を渡す」を追加**（利用者の了承済み）
   設計書を揃えても「完成の条件」と「順番」が無いとAIは次の一手を提案できないこと、地図はループの「目標・合格条件」の部品にあたること、要件と地図を往復しながら育てることを書いた。

4. **`docs/00-roadmap.md` を壁打ちの結果で修正**（利用者の了承済み）
   - 利用者から「UIの見直しが必要」「ログイン前に用意された素材で試せる方がよい」「作るものを固めないと安全対策も手戻りになる」との指摘を受け、段階0「プロダクトを固める」を新設した。決まったこと（主な利用者は絵が描けない原作者と自分で描く人の両方、ネーム向け素材の自作を主軸にする、ネームと完成漫画の両方を目指し共通の作業を先に作る、ログイン前のお試し）と、まだ決まっていないことを書いた
   - 段階1（安全）は段階0の後に移した。本番の登録者が開発者本人だけで急ぐ必要がないことと、認証の方式がお試しの有無で変わることが理由。他の人に使ってもらう前に必ず終える、と明記した
   - 段階2を「プロトタイプを作る」に変え、段階3「限定公開で反応を見る」を新設してアクセス解析をここへ前倒しした（全7段階に）
   - 広告審査の条件の調査は段階0に移した

5. **`.gitignore` に `CLAUDE.local.md` を追加**（利用者の了承済み）
   Claude Code が自動で読み込む個人用のメモファイル（`CLAUDE.local.md`）を、公開リポジトリに含めないようにした。
