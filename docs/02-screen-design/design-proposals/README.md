# デザイン案（design-proposals）

> 画面の配色・ボタンの形・タイポグラフィ・全体の質感を決めるために作成した、デザイン調査の資料。
> ヘッダーとサイドメニューの構成は、[wireframes](../wireframes/) と各画面の[仕様書](../specifications/)のとおりとし、見た目だけを比較している。

---

## 1. 見方

[index.html](index.html) をブラウザで開くと、すべての案を1画面で見比べられる。

- 左の一覧で案を選ぶと、右に画面が表示される
- 右上の「ホーム／漫画作成」で、表示する画面を切り替えられる（漫画作成画面は A・B の6案のみ）
- 漫画作成画面を表示したまま案を切り替えると、配置はそのままで見た目だけが変わる（テーマ切り替えのイメージ）
- 「別タブで原寸表示」で、各案を1440px幅の原寸で開ける

各案は1ファイルで完結している。ただしフォントは Google Fonts から読み込むため、正しく表示するにはインターネット接続が必要。

## 3. 3つの方向と各案

フォントはすべて Google Fonts で配信されている実在の書体。文字と背景のコントラストは WCAG AA（4.5:1）以上を目安にしている。

### A ニュートラル・メディア型

動画・メディアサイトに多い、白とグレー基調の考え方。白とグレーで画面の枠（クロム）を目立たせず、ユーザーのメモや原稿を主役にする。

| 案 | コンセプト | アクセント色 | フォント | ボタンの形 |
|---|---|---|---|---|
| A1 | ホワイト・キャンバス | 藍 `#2741B8` | Zen Kaku Gothic New ＋ Manrope（ロゴ・数字） | ピル型（両端が丸い） |
| A2 | クールグレー・ワークベンチ | ティール `#0B7064` | IBM Plex Sans JP ＋ IBM Plex Sans Condensed（ロゴ） | 角丸6px、選択中は左側の線 |
| A3 | ウォーム・アーカイブ | 葡萄 `#74306E` | Murecho ＋ Bricolage Grotesque（ロゴ） | 角丸10px、切り替えは下線タブ |

### B 原稿・制作道具型

漫画制作の現場の道具（原稿用紙、Gペンのインク、スクリーントーン、ネームの青鉛筆、コマ枠線）から見た目の要素を借りた、明るい制作ツール。

| 案 | コンセプト | アクセント色 | フォント | ボタンの形 |
|---|---|---|---|---|
| B1 | ネーム帳 | ネーム水色 `#1767BE` | Zen Kaku Gothic New ＋ Klee One（手書き風）＋ Dela Gothic One（ロゴ） | 墨の輪郭＋版ズレのような影 |
| B2 | 入稿前の赤ペン | 赤ペン `#C42A22` | Murecho ＋ Shippori Mincho B1（作品名・セリフ） | 細い輪郭＋太い下線。カードの四隅にトンボ |
| B3 | コマ割り定規 | 製図藍 `#3236A3` | BIZ UDPGothic ＋ Zen Old Mincho（作品名）＋ Rampart One（ロゴ） | コマ割りの斜線のように傾けた枠 |

### C カラフル・アセット整理型（見送り）

メモ・ストーリー・漫画を色で見分けられる、親しみやすいワークスペース。ホーム画面のみ作成。

| 案 | コンセプト | 特徴 | フォント |
|---|---|---|---|
| C1 | ふせんボード | パステルの付箋、ピル型 | Zen Maru Gothic ＋ Mochiy Pop One（ロゴ） |
| C2 | カラーインデックス | 山吹・青・紅で種類を色分け、キーキャップ型のボタン | LINE Seed JP ＋ Outfit（ロゴ・数字） |
| C3 | 若葉トーン | 緑1色の濃淡7段階、葉っぱ形のカード | M PLUS Rounded 1c ＋ Kiwi Maru |

## 4. 漫画作成画面での検証結果

### 判定

| 案 | 判定 | 理由 |
|---|---|---|
| A1 ホワイト・キャンバス | ◎ | 最も静かで、原稿が素直に主役になる |
| A2 クールグレー・ワークベンチ | ◎ | 「作業台」というコンセプトが、ホーム画面より編集画面で活きる |
| A3 ウォーム・アーカイブ | ○ | 統一できる。ただし作業スペースが暖色寄りのグレーのため、長時間の作業でトーンの見え方にわずかに影響する可能性がある。下線タブは、小さな部品では選択中の表示がやや弱い |
| B1 ネーム帳 | ◎ | 線と白で組む見た目が、そのままプロ向けツールらしくなる |
| B2 入稿前の赤ペン | ◎ | 「赤は印を付けるときだけ」というルールが、選択中の表示とそのまま重なる |
| B3 コマ割り定規 | ○ | 統一できる。ただし選択中の表し方が3種類（斜めの枠・マーカー・網点）あり、道具の多い編集画面ではややにぎやか |

### 6テーマ共通のルール

- **原稿には色を付けない**：原稿用紙は純白 `#FFFFFF`、コマ枠は黒 `#111` に固定する。ユーザーの作画（白黒の線画とトーン）が正しく見えるようにするため
- **作業スペースは濃いめのグレー**：原稿の周りは、各テーマの色味に合わせた濃いグレー（`#41444F`〜`#5F6368`）。白い原稿が浮き上がって見える
- **主ボタンは1つだけ**：アクセント色で塗るのは「見開きを書き出す」のみ
- **選択中の表し方をホーム画面とそろえる**：フォルダ・ページ・素材チップの選択中は、ホーム画面のサイドメニュー・表示切り替えと同じ表し方にする

### 気づいた点（本実装で検討すること）

- 素材フォルダの帯は横スクロールのため、右端の「追加」ボタンが最初は隠れている。本実装では「追加」を帯の外に固定するのがよい
- B2 は、見開きの間の溝で四隅のトンボがやや重なって見える
- B3 の素材チップは、選択中の網点の上の小さい文字が少し読みにくい。選択中は藍の塗りにするほうが安全
- ホーム画面の A・C の一部には、ワイヤーフレームにない「メモを書く」などのボタンが追加されている

## 5. テーマ切り替えの仕組み（漫画作成画面）

「配置は1つ、見た目だけを設定で切り替える」方式が成り立つかを確かめるため、漫画作成画面は次の構成で作っている。

```
editor/
├── A1〜A3.html, B1〜B3.html   ← 完成版（ブラウザで開く用）
└── source/                      ← 元データ
    ├── skeleton.html            ← 共通の骨組み（HTML と配置の CSS）
    ├── themes/A1〜B3.css        ← テーマごとの見た目の CSS
    └── build.py                 ← 骨組みとテーマを合体して完成版を作るスクリプト
```

- **骨組み（skeleton.html）**：すべてのテーマで共通の HTML。ボタンの位置、領域の幅（ヘッダー内の各ブロック、ページ一覧 168px、素材一覧 280px）、ヘッダーの高さ（132px）、ツールバーの高さ（56px）は、`<style id="layout">` で固定している
- **テーマ（themes/*.css）**：色・フォント・枠線・角丸・影・ボタンの形・選択中の表し方だけを指定する。配置を変える指定（領域の幅や並び順など）は書かないルール
- 6テーマとも同じ骨組みで成り立ったため、本実装でも「レイアウトの CSS」と「テーマの CSS（CSS 変数など）」を分けておけば、設定画面からのテーマ切り替えは実現できる見込み

### 完成版を作り直す方法

テーマの CSS や骨組みを変更したときは、次のコマンドで完成版の HTML を作り直す（Python 3 が必要）。

```bash
cd docs/02-screen-design/design-proposals/editor/source
python3 build.py        # 全テーマを作り直す
python3 build.py A1     # A1 だけ作り直す
```

テーマの CSS の先頭2行には、テーマ名と Google Fonts の URL を書く（build.py が読み取って HTML に入れる）。

```css
/* name: ホワイト・キャンバス */
/* fonts: https://fonts.googleapis.com/css2?family=...&display=swap */
```

## 6. 注意

- これは調査用の資料で、アプリ（`RebuildReact/`）には反映していない
- 画面内の文章やイラストはすべて架空のダミー。実在の作品・人物は含まない。漫画作成画面の素材は、簡単な図形で描いた仮のイラスト
- モックアップは幅1440pxで作成している（漫画作成画面は 1440×900 を想定）。スマートフォン幅には対応していない
