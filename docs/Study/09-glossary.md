# 09. 用語集

このノートに出てくる用語を、初学者向けに説明します。

## 開発の進め方

| 用語 | 説明 |
|---|---|
| ループエンジニアリング | AIが実装し、機械が検証し、失敗したら直す、という繰り返しを回す開発スタイル。詳しくは [03](03-loop-engineering.md) |
| CLAUDE.md | AI（Claude Code）が作業のたびに読む、決まりごとのファイル |
| ガードレール | AIが危険な操作をしないように、あらかじめ決めておく歯止め |
| Hooks | 特定のタイミング（ファイル保存時など）に、自動で実行される処理。ルールを機械で強制するために使う |
| ミューテーション確認 | 本体のコードをわざと壊して、テストが本当に失敗するか確かめること |
| デザイントークン | 色・フォント・角丸などの見た目の値に、役割の名前を付けて1か所にまとめたもの。テーマ切り替えの土台になる（[02](02-design-decisions.md)） |
| CSS変数 | CSSの中で使える変数（`--color-accent: #2741B8;` と定義し、`var(--color-accent)` で使う）。デザイントークンの入れ物 |

## Git / GitHub

| 用語 | 説明 |
|---|---|
| ブランチ | 本編（main）に影響を与えずに作業できる、作業用の枝 |
| コミット | 変更を、メッセージつきで記録すること |
| push | 手元の記録を、GitHubに送ること |
| PR（プルリクエスト） | 「この変更を、mainに取り込んでください」というお願いと、確認の場 |
| マージ | ブランチの内容を、mainに取り込むこと |
| ff-only | 履歴を書き換えず、位置を進めるだけのマージ方式 |
| コンフリクト | 同じ場所を別々に変更して、自動では取り込めない状態 |
| ブランチ保護 | 「CIが成功しないとマージできない」などを強制する、GitHubの設定 |

## CI / CD / クラウド

| 用語 | 説明 |
|---|---|
| CI | push のたびに、テストなどを自動で実行して、壊れていないか確認すること |
| CD | 確認が済んだものを、自動で本番に反映すること |
| GitHub Actions | GitHubが提供する、自動実行の仕組み。設定は `.github/workflows/` のYAMLに書く |
| ワークフロー | GitHub Actionsで実行する、一連の処理の設定 |
| Secrets | パスワードや鍵を、GitHubに安全に保存する仕組み |
| OIDC | 長期間有効な鍵を使わず、一時的な権限でAWSなどに接続する認証方式 |
| S3 | AWSのファイル保存サービス。このプロジェクトでは、フロントエンドの置き場 |
| CloudFront | AWSの配信サービス（CDN）。S3の内容を、世界中に速く届ける。キャッシュを持つ |
| EC2 | AWSの仮想サーバー |
| IAM | AWSの、誰に何を許可するかを管理する仕組み |
| 最小権限 | 必要な権限だけを与える、という考え方 |
| セキュリティグループ | EC2の「入口の許可リスト」。どこから、どの番号の入口（ポート）に入ってよいかを決める |
| SSH / 鍵ペア | サーバーに、文字のコマンドで安全に接続する仕組み。接続には、作成時の鍵ファイル（`.pem`）と、OSごとのユーザー名（Ubuntuなら `ubuntu`）が必要 |
| DNS | 「`mangarebuild.com`」のような名前を、サーバーの住所（IPアドレス）に変換する仕組み。インターネットの電話帳 |
| NXDOMAIN | DNS の答えで「その名前は存在しない」という意味。サーバーにたどり着く前のエラーなので、アプリのログには残らない |
| Route 53 | AWSの DNS とドメイン登録のサービス。Rebuild のドメインもここで登録している |
| `clientHold` | ドメインの状態の1つ。登録会社が、ドメインをインターネットに出さないよう保留にしている。登録者のメールアドレスを確認していないときなどになる |
| JWT | ログインした本人であることを示す「合言葉」。中身（ユーザーIDや有効期限）に、サーバーだけが知る鍵で署名してある。署名があるので、中身を書き換えると偽物だと分かる |
| Authorization ヘッダー | 通信に付ける「身分証」の欄。JWT は `Authorization: Bearer 合言葉` の形で送る |
| 後方互換 | 新しいものが、古いものと組み合わせても動くこと。本番に出る順番がずれても壊れないようにする |
| WAF | Webへの攻撃を、サーバーに届く前に止める仕組み。Rebuild ではAPI用の CloudFront に付いている |
| マネージドルール | AWSが用意した、WAFの標準のルールのセット。中には「8KBを超える送信を止める」（`SizeRestrictions_BODY`）のように、普通の使い方まで止めてしまうものもある |
| ブロック / カウント | WAFのルールの動作。ブロックは止める、カウントは止めずに記録だけする |

## バックエンド・テスト

| 用語 | 説明 |
|---|---|
| Spring Boot | Javaで、Webのバックエンドを作るためのフレームワーク |
| JPA / Entity | JavaのクラスとDBのテーブルを対応づける仕組み。Entityは、1つのテーブルに対応するクラス |
| BCrypt | パスワードを、元に戻せない形に変換（ハッシュ化）する方式 |
| JWT | ログイン後に発行される、本人確認用の署名つきの文字列（目標の設計。現状は未実装） |
| CORS | 別のオリジン（ドメインやポート）からのアクセスを、許可するかどうかの仕組み |
| オリジン | 「`https://` などの方式＋ドメイン＋ポート」の組み合わせ。`localhost:5173` と `localhost:8080` は別のオリジン |
| プリフライト（OPTIONS） | ブラウザが本番のリクエストの前に、「このサイトから、この操作をしてよいか」をサーバーに確認する問い合わせ |
| キャンバスの汚染 | 許可なく読み込んだ別オリジンの画像を描いたキャンバスは、ブラウザがPNGへの変換などを禁止する。`crossOrigin = "anonymous"` で読み、配信側が許可すれば防げる |
| トランザクション | 複数のDB操作を「全部成功するか、全部なかったことにするか」のひとまとまりにすること。「削除してから入れ直す」処理などで必要 |
| 派生クエリ（Spring Data） | `findByStoryId` のようなメソッド名から、検索を自動で作る仕組み。名前の解釈がずれることがある |
| MockMvc | HTTPリクエストを疑似的に送ってテストする道具 |
| `@Transactional` | 処理を1つの単位にまとめる。テストでは、終わったあとにDBの変更を巻き戻すために使う |
| `@TempDir` | テスト中だけ使える、終わると消える一時フォルダ |
| contextLoads | アプリが起動できるかを確認する、最も基本のテスト |

## データベース

| 用語 | 説明 |
|---|---|
| 正規化 | 同じ情報が重複しないように、テーブルを分けること |
| 外部キー（FK） | 他のテーブルの行を指す列。存在しない行を指すデータを、DBが防ぐ |
| 中間テーブル | 多対多の関係（例：ストーリーとジャンル）を表すためのテーブル |
| マイグレーション | DBの構造の変更を、履歴として管理しながら適用すること（未整備） |

## Docker

| 用語 | 説明 |
|---|---|
| コンテナ | アプリを、環境ごとまとめて動かす入れ物。使い捨てが基本 |
| イメージ | コンテナの元になる設計図。コードを変えたら、再ビルドが必要なことがある |
| ボリューム | コンテナの外にデータを残す仕組み |
| Docker Compose | 複数のコンテナ（フロント・バック・DB）を、まとめて起動する設定 |
