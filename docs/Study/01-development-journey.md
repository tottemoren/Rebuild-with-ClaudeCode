## 段階ごとの考え方

### 1. 機能の土台（8月上旬）

**やったこと**：パスワードをそのまま保存せず、BCryptで暗号化（ハッシュ化）して保存するようにしました。画面では、ドラッグでコマ画像を配置し、枠内をPNGとして保存できるようにしました。

**考え方**：個人情報（パスワード）の扱いは、後から直すほど影響が大きくなります。そのため機能が少ない早い段階で入れました。

**学んだこと**：保存方法を変えると、既存のデータが使えなくなることがあります。平文で保存済みのユーザーは、ハッシュ化後はログインできなくなるため、再登録が必要でした。**仕様変更は、既存データへの影響まで考える**必要があります。

<sub>作業記録：[2026-08-08](../docs/ClaudeCode%20CHANGELOG/2026/08/2026-08-08.md)</sub>

### 2. 設計書を整える（8月中旬）

**やったこと**：画面のワイヤーフレームから画面仕様書を作り、要件定義、システム設計、データベース設計、API設計へと広げました。

**考え方**：コードを書く前に「何を作るか」を言葉と図にしておくと、AIに指示するときも、自分で見直すときも、判断の基準になります。

**学んだこと**：設計書を書く過程で、コードだけを見ていたときには気づかなかった問題が見つかりました（例：メモに `user_id` がなく、全ユーザーで共有されてしまう）。**設計書は、問題を見つける道具にもなります**。詳しくは [02. 設計判断と理由](02-design-decisions.md) を参照してください。

<sub>作業記録：[2026-08-11](../docs/ClaudeCode%20CHANGELOG/2026/08/2026-08-11.md)、[2026-08-13](../docs/ClaudeCode%20CHANGELOG/2026/08/2026-08-13.md)、[2026-08-18](../docs/ClaudeCode%20CHANGELOG/2026/08/2026-08-18.md)、[2026-08-28](../docs/ClaudeCode%20CHANGELOG/2026/08/2026-08-28.md)</sub>

### 3. 本番公開の準備（8月下旬〜9月）

**やったこと**：
- ソースコードに直接書いていた `http://localhost:8080`（26か所）を、環境変数（`VITE_API_BASE_URL`）に置き換えました。
- フロントエンドを、S3 + CloudFrontへ自動デプロイするワークフローを作りました。
- 独自ドメインを取得し、SSL証明書を設定しました。

**考え方**：接続先をコードに直接書くと、環境ごとに書き換える手間と間違いが生まれます。環境変数にすれば、開発用と本番用を同じコードで切り替えられます。

**学んだこと**：自動デプロイの認証で、推奨されるOIDC方式が原因不明のまま失敗し、アクセスキー方式に切り替えました。**完璧を求めて止まるより、動く形を先に作り、残った課題を記録する**という判断をしました。詳しくは [08. つまずきと解決](08-troubleshooting.md) を参照してください。

<sub>作業記録：[2026-09-23](../docs/ClaudeCode%20CHANGELOG/2026/09/2026-09-23.md)、[2026-09-24](../docs/ClaudeCode%20CHANGELOG/2026/09/2026-09-24.md)、[2026-09-25](../docs/ClaudeCode%20CHANGELOG/2026/09/2026-09-25.md)、[2026-09-29](../docs/ClaudeCode%20CHANGELOG/2026/09/2026-09-29.md)</sub>

### 4. 画面の整理（9月下旬）

**やったこと**：似た役割のヘッダーやレイアウトのファイルを、1つにまとめました（`Header` と `MainLayout` に統合）。広告枠の有無は、`showAdvertisement` という設定値で切り替える形にしました。

**考え方**：ほぼ同じ内容のファイルが複数あると、片方だけ直して食い違いが生まれます。違いが「設定値で表せる程度」なら、1つにまとめるほうが安全です。

**学んだこと**：まとめる作業の途中で、レイアウトの高さが崩れる不具合が出ました（高さの基準になる親要素に高さを指定し忘れていた）。**大きな整理は、見た目の確認と、小さな段階ごとの確認が欠かせません**。

<sub>作業記録：[2026-09-29（重複整理）](../docs/ClaudeCode%20CHANGELOG/2026/09/2026-09-29-header-layout-refactor.md)、[2026-09-29（設計書に合わせる）](../docs/ClaudeCode%20CHANGELOG/2026/09/2026-09-29-header-layout-design-alignment.md)、[2026-09-30](../docs/ClaudeCode%20CHANGELOG/2026/09/2026-09-30-layout-consolidation.md)、[2026-10-01](../docs/ClaudeCode%20CHANGELOG/2026/10/2026-10-01-createmanga-header-fix.md)</sub>

### 5. 検証の仕組みを作る（10月）

**やったこと**：バックエンドのCIを追加し、メモとフォルダ/素材のAPIテストを書き、CLAUDE.mdを見直しました。

**考え方**：AIに実装を任せる量が増えるほど、「正しく動いているか」を人間が毎回目で確認するのは現実的でなくなります。**機械が自動で検証する仕組み**を先に作りました。

**学んだこと**：次の3つです。詳しくは各ノートを参照してください。
- 「テストがある」だけでは足りず、**壊れたときに本当に失敗するか**の確認が必要（[05](05-testing.md)）
- AIには**守らせるルールを文章で渡す**だけでなく、**機械で止める仕組み**も必要（[07](07-working-with-ai.md)）
- この流れ全体は、[03. ループエンジニアリング](03-loop-engineering.md) の考え方に沿っています

<sub>作業記録：[2026-10-05](../docs/ClaudeCode%20CHANGELOG/2026/10/2026-10-05.md)、[2026-10-06](../docs/ClaudeCode%20CHANGELOG/2026/10/2026-10-06.md)</sub>

### 6. 見た目と中心機能をつなぐ（10月12〜13日）

**やったこと**：デザイン案を9つ作って比べ、A1「ホワイト・キャンバス」を全画面に適用しました。続けて、漫画作成画面が実はサンプル画像でしか動いていなかったことに気づき、自分でアップロードした素材で「配置 → 保存 → PNGで書き出し」まで通るようにしました。

**考え方**：見た目の作業は、土台（デザイントークン）→ 共通の枠 → 各画面、の順に小さく進め、段階ごとにブラウザで確認してコミットしました。見た目の作業の途中で中心機能のずれが見つかったので、優先度を入れ替えて機能を先につなぎました。

**学んだこと**：
- 見た目は**実物を並べて比べる**と決めやすい（[02](02-design-decisions.md) #10）
- 見た目の作業は、隠れていた機能の問題を見つけるきっかけにもなる
- 不具合は、**テストで再現してから直す**（[05](05-testing.md)）

<sub>作業記録：[2026-10-12（1回目〜8回目）](../docs/ClaudeCode%20CHANGELOG/2026/10/2026-10-12.md)、[2026-10-13（1回目〜4回目）](../docs/ClaudeCode%20CHANGELOG/2026/10/2026-10-13.md)</sub>

### 7. 本番の調査（10月13日）

**やったこと**：本番で、ローカルと違う動きが見つかりました。バックエンドの修正がEC2に反映されていなかったことと、API用 CloudFront の WAF が画像のアップロードを止めていたことが原因でした。EC2への反映とWAFの設定変更で直し、実態と違っていた CLAUDE.md を直しました。

**考え方**：本番の操作は利用者が行い、AIは手順と原因の切り分けを担当しました。調べるときは、**データを変えない方法**を選びました。

**学んだこと**：
- **ローカルで動くのに本番で動かないときは、間にある仕組み（CloudFront・WAF）を疑う**（[08](08-troubleshooting.md) #14）
- フロントは自動、バックエンドは手動で反映される構成では、**片方だけが本番に出る**ことがある。自動デプロイがあれば防げる
- **記録が古いと、AIも人も間違える**（[07](07-working-with-ai.md)）
